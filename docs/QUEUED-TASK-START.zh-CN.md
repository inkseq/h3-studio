## 新行为

新策略显式使用 `qualification_profile: queued-task-first-v1`，对应执行策略 `qualification.status: runtime_required` 和相同的 `profile`。它是启动/验证策略，不是上游 model ID。旧策略和旧租赁回执保持原有行为，不能在活动周期中改字段跳过原来的验收。

1. 用户确认提交后，保留原任务、请求、幂等键、额度预留与容量审批。
2. 按既有条件选机、预算与 TTL 启动。校验固定部署源码、ComfyUI 和模型版本、权重文件大小、硬件/显存及运行环境，并核对上游队列确实空闲。
3. 注册可执行真实任务的工作机。此时只说明环境检查完成，`generation_verified` 仍为 false；不提交任何额外验收视频。
4. 正常队列领取第一个真实任务，通过现有一次提交、轮询、视频/音频校验和私有结果入库链路执行。成功后同一结果直接交付用户，不再重复生成一次。
5. 成功记录绑定具体实例、工作机、真实任务与请求范围，不代表所有输入模式、全部参数或其他新 GPU 都已经通过。

首任务可能就是首尾帧或混合参考任务，没有强制先跑文字生成。移除测试视频并不移除模型下载、环境初始化或真实任务的首次模型加载；优化后的开机时间尚未在线实测，不承诺固定分钟数。

## 失败与重启

- 明确执行或结果校验失败：保留原任务、尝试记录与安全错误码，暂停这台工作机领取新任务；不自动把原任务改成 queued 或另建任务。
- 上游提交结果不明：继续持有原任务/实例绑定，按原任务标签和尝试对账；不能因超时重新 POST，也不能因为列表暂时为空就另租机器。
- 用户取消：沿用原取消流程，不伪称生成成功，不把主动取消当成硬件故障。
- 工作机进程重启：验证实例/配置绑定和持久暂停记录，不能借重新启动把失败工作机变成 ready。原有上游任务仍优先对账/收集。
- 若需要换机或重试，必须在确认原上游任务停止、原实例销毁/账单完成且原预算和恢复条件允许后走独立恢复流程；本策略不自动授权额外重试或充值。

新策略只复用原受限输入与控制范围，不扩大到原生9图/3视频/3音频、不更换模型或解码参数。账户隔离、取消、幂等、容量锁、已接收任务、租赁账本与空闲600秒关闭规则保持。
