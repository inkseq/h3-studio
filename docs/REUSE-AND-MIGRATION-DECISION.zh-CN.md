## 1. 决策：目标架构重新梳理，实现按模块渐进改造

推荐在现有仓库、现有统一平台上做**有明确边界的模块化和局部替换**。保留已有账户/权限、素材、任务账本、预算、恢复和成片身份；把 HTTP 层、场景业务、引擎协议和运行政策之间的耦合逐步拆开。需要新实现的模块可以重写内部，但通过同一合同接回现有系统。

这不等于继续随意补丁，也不要求把旧代码全部整理好才给用户生成视频。每个工作包必须交付一条可验证的行为改善，且保持旧任务可解释、旧结果可取回。

| 选择 | 对本项目的实际代价 | 判断 |
|---|---|---|
| 新建一套后端、数据库和调度后一次切换 | 重新实现归属/幂等/取消/收集/预算；迁移故事、素材、API Key、任务和未知租赁；旧系统仍须维护 | 当前没有证据证明收益值得这些成本，不推荐 |
| 保持结构，继续逐故障加分支 | 短期修得快，长期仍混淆执行配置、场景和控制器政策 | 只用于必要修复，不能作为长期路线 |
| 现有平台原地模块化，局部替换引擎/政策 | 可保留真实数据和已有保护；需要清楚的接口及迁移退出条件 | 推荐 |

重新评估整套重写的条件是：关键数据模型无法表达已确认需求，权限/事务基础无法修复，或最小提取实验已经证明兼容成本明显超过替换成本。当前检查尚未发现这样的证据。文件长、目录多、名字旧，都不足以证明需要重写。

方法参考：先识别可替换边界，再逐块交付，符合 [Strangler Fig](https://martinfowler.com/bliki/StranglerFigApplication.html) 的增量迁移思路；在统一接口后替换实现，符合 [Branch by Abstraction](https://martinfowler.com/bliki/BranchByAbstraction.html)。这是方法依据，具体保留哪些代码仍由下面的本地证据决定。

## 3. 真正需要拆开的耦合

### 3.1 业务服务反向依赖 HTTP 组装

`api.py:473` 的计划编译/保存闭包、授权函数、公共响应函数，通过 `GenerationAdmission` 构造参数、`app.state` 和 QuickChatHooks 被其他模块调用（`api.py:603`、`:668`、`:683`）。模块名称已经分开，但业务离开 create_app 后仍不容易独立组合。

目标是把授权检查、PlanService、GenerationAdmission 和响应投影分成明确接口；路由只做请求解析、调用和序列化。现有事务边界保持完整，不能把一个原子接单拆成几次 HTTP 调用。

### 3.2 公共能力校验直接生成 Comfy 节点图

`capabilities.py:11` 引用 `comfy_workflow`，`:260` 调用 `build_workflow` 验证请求。新引擎不能只替换 Worker 的 HTTP 地址，否则公共预检仍被 Comfy 图和控制语义绑住。

目标分三步：通用素材/业务校验 → 版本化 recipe/硬件包络校验 → 引擎编译。现有 Comfy 编译器继续解释旧请求；WanGP 使用显式、版本化参数映射，未知映射在提交前拒绝。B2提取没有完成这一层解耦；不能机械照抄同名参数、套用 WanGP 默认精度/步数或改写已接收请求。

### 3.3 直接生成被强制映射成故事镜头

`capabilities.py:173–184` 要求 project/shot/shot_version；Quick Chat 为此维护隐藏执行投影。它现在是有效兼容桥，并非可以立即删除的垃圾数据。

后续拟引入有持久归属的 `source_ref` 与不可变请求，让 direct creation 无需伪造故事；这不是当前已有的独立生成端点。切换前旧 plan/job 仍按旧来源校验。隐藏投影只能有一处生成权威，不能让场景和镜头各自编辑同一请求。

### 3.4 按需生产服务继承有限验收规则

`on_demand_scaler.py` 建立在 FiniteController 之上。其校验包含固定两个用户名、最大一台 GPU、最多八个周期等约束。改变这些值前要先区分持续服务政策、单周期预算、节点能力和测试安全范围。

真正要重构的是政策与编排边界。不是把所有限制删掉，也不是重新实现租赁账本。双机要求还需要逐节点故障隔离，不能把原单节点 cycle hold 原样提升到整个池。

已有可简化的实例：五小时延期在 FiniteConfig、部署和交接校验中重复限定为 `0/18000`。后续应由同一份受验证截止时间/授权配置表达，保留原账本，不再每次添加专用代码分支。跳过资格视频则改变就绪证据和失败隔离行为，不能仅删除检查；应收敛为统一启动策略及证据处理。C1解决这类耦合，不要求先重写整个租赁协调器才做单槽真实验证。

### 3.5 独立部署尚有真实前置条件

AssetService 使用本地 staging 和 OS 锁，HTTP 准入有进程级状态；因此增加 API 容器副本不自动获得一致的上传/限流行为。`auth.py:46` 的用户集合也仍是两个测试账户。

这些是明确的局部工作包：共享准入/资产操作租约、跨主机暂存策略、用户目录。可保留现有权限语义，不能仅加负载均衡或注册页就称为公众生产服务。

### 3.6 发布指纹比模块名更宽

`tools/release_contract.py:15–25` 与 `:29–40` 将大部分后端源码计入兼容指纹，只少量排除前端服务/发现模块。拆成文件并不会自动使发布独立。

后续以真实协议版本和依赖边界拆发布范围，先证明 API、worker、runtime 可以兼容组合。不能为了加速 CI 随意缩小哈希范围，让活动任务使用未经验证的新解释器。

## 4. 名字相近的 GPU 文件，多数不是重复实现

当前按需模式的主要链路如下；它是代码调用关系，不是今天线上健康证明：

```text
deploy/platform/gpu_scaler.py
  → scaler_entry → OnDemandController
    → ServiceCycle / FiniteController
      → ScaleCoordinator → autoscale.recommend
      → ProductionBoot / FleetSupervisor
        → QueuedTaskRunner → DrainSafeRunner → WorkerRunner → inference/ComfyBackend
```

- `autoscale` 给建议，`scaler` 执行受持久账本约束的租赁，`fleet` 管执行进程；三者不是同一个功能重复三遍。
- `QueuedTaskRunner` 加上真实任务证据与失败隔离；`DrainSafeRunner` 保证停止领新任务后仍继续收集/对账。不能简单合并掉后者，导致已经生成的视频取不回来。
- `production_scaler` 是 on-demand 的基础，不是看到名字旧就可删除。
- `production_worker.py` 是已租并已交接单卡的有限验收入口，不是当前通用 Worker；`deploy/platform/gpu_acceptance.py` 仍引用它。只能作为最后退役的候选。

新引擎接入还要覆盖结果合同：现有收集器需要视频及独立音频等输出证据。新引擎只返回含音轨 MP4 时，adapter 必须明确归一化和验证，不能把“HTTP 成功”当作接口等价。

## 6. 文档先写到什么程度

先补足会影响下一批实现的合同，不先给全部历史代码写完百科。每个改造模块要有：当前入口与行为、目标行为、输入/输出、状态及副作用、唯一数据权威、兼容/退出条件、验收和负责人。

文档分工固定为：

1. **索引**：告诉新会话去哪读，不复制所有设计正文。
2. **总规划**：目标架构、API 方向、技术栈和 A–H 实施顺序。
3. **当前行为契约**：现有接口、代码位置与兼容约束；与目标提案明确区分。
4. **当前工作包 spec**：这一批改变什么、保留什么、如何判定完成；实现发现回写本包。
5. **验收/发布回执**：说明什么版本、在哪个环境、何时验证过；历史成功不是实时健康。

已确认的文档冲突登记：

| 冲突 | 本轮处理/后续入口 |
|---|---|
| START-HERE 仍以“未上线、CPU模拟”描述早期状态 | 加历史标识并引导新索引；不将其当今天状态 |
| ARCHITECTURE 早期部署叙述与后续 EC2/DNS 回执不同 | 索引明确它是带日期的实现基线；部署事实读后续回执并重新核验 |

本轮不替另一个正在开发的会话批量改其产品规格或接口；将差异明确登记，后续由对应工作包统一回写。现有文档描述某行为不代表该行为正确；发现用户决定与代码冲突时要修正实现，不能为了“文档一致”冻结错误行为。

## 7. 具体从哪一批开始

沿用总规划 A–H，不再建立一套竞争的路线图。

| 批次 | 先形成的文档 | 实际改造 | 验收与退出条件 |

| A：整理事实与合同 | 当前入口图、模块归属、现有字段/错误/状态映射；标清本地与生产版本 | 只做必要类型与观测准备 | 所有人对同一调用链、数据归属和开放范围有一致理解 |

| B/C：真实闭环与恢复 | 阶段/错误/恢复表和受控验收计划 | 修清楚服务政策、启动准备、等待原因、收集恢复 | 授权后同一个真实任务完成上传→按需开机→下载；失败有证据、有出口 |
