## 服务行为

- 网站、登录、故事编辑、上传、预检由常驻 CPU 服务处理，不触发 GPU 创建。
- 用户明确提交通过预检的生成任务后，原任务进入 `waiting_capacity`。控制器从真实持久任务触发一台 GPU；启动、模型加载与独立资格检查后执行同一个任务。
- `superdan`、`supervan` 的当前及新故事共用单卡队列，账号、素材、结果和 Key 隔离继续由业务 API 保证。
- 运行中、排队、未知上游状态、结果下载和入库都不能算空闲。确认业务和 GPU 均空闲后，持久计时满 600 秒才进入 drain/销毁。新任务重置计时，不按最近一次提交时间中断长任务。
- 新任务与已承诺关机恰好冲突时，未接收的新提交返回明确的 `capacity_drain_repreflight`，不创建任务或扣预留；客户端保留作品并要求重新预检。已经接收的任务不因这次竞态被丢弃。
- 每个租赁周期有唯一审批、意图和账本；只有旧实例的供应商销毁事实及安全工作状态确认后才开始下一周期。丢创建响应只核对，不重复租用。
- 此轮最多一台单卡；没有以假积压触发第二台，也没有启用未验收的多卡扩容。

## 费用和运行边界

沿用 GPU US$50 总授权，之前最终供应商费用 US$3.490345，本次租赁可用上限 US$46.509655。按需配置最多 8 个周期、单次不超过 4 小时 TTL，单卡报价上限 US$1.40/小时，每周期保守预留 US$5.60。供应商实际报价每次创建前复核；该提供商不支持原子价格上限，不能把预查称为绝对账单保证。不充值、不提高预算、不自动延长实例 TTL。

操作员授权窗口最多 24 小时，接近截止、预算不足或未知资源状态时停止新租赁，并完成现有对账。它是本轮有限测试授权，不代表无限期付费服务。Job 预算是准入预留，与供应商账单分别记账，不将两者相加冒充实际费用。

## 实现与验证

- `studio_platform/on_demand_scaler.py`：跨周期按需服务；复用已有有限控制器、实际 PostgreSQL、素材存储和 provider 账本。
- `studio_platform/scaler_entry.py`：受限配置选择按需或原有限模式。
- `studio_platform/production_scaler.py` / `production_scaler_boot.py`：显式双账户所有故事范围，旧单故事配置语义保持。
- `studio_platform/scaler.py`：持久业务空闲时钟及关闭前事务检查。
- `studio_platform/repository.py`：空闲关闭与提交使用同一容量锁；幂等重试优先返回已有任务。
- `deploy/platform/gpu_scaler.py`：受保护配置、凭据只经一次 stdin、控制器审批就绪后才开启网页生成；常规发布及其他控制器不能覆盖活动周期。

离线模拟测试覆盖零任务零创建、真实冷等待、同任务激活、600 秒关闭、途中新任务复用及重置、下一账户新故事再次触发、未知创建不重投、累计预算保留、并发提交与销毁保护。它们不代表这轮发生了真实推理。
