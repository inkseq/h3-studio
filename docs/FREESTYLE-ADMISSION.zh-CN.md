# 快速创作：先选方式，并区分排队许可与运行验证

## 用户问题和验收标准

用户在左侧添加图片时，决定输入用途的 H3 方式藏在右侧；服务器又只开放纯文字 FL50。首尾帧或 Ref 预检失败时，原代码还会附带错误的“没有冷启动审批”信息，即使真正原因是配方或输入超出开放范围。

- 先在素材区上方选择“文生 / 首尾帧”或“全能参考”，再准备对应输入；手机布局保持这个顺序。
- 切换方式保留提示词、参数、素材和关联；不能为通过预检偷偷丢掉用户的参考输入。不兼容关联由用户明确处理。
- 右侧显示当前方式，不再重复设置同一选项；短剧镜头面板仍保留自己的方式选择。
- 选择后立即显示服务器实际开放范围。模型接口的 9 图 / 3 视频 / 3 音频不是每个云配置都已验证的范围。
- 输入或控制不匹配时显示具体原因，不附带未经检查的容量或冷启动错误。
- `runtime_required` 只表示运营允许在对应范围内排队。GPU 启动后必须完成对应套件，才注册 worker 并运行用户任务。网页、API 不称其已经实测通过。
- 打开网页、编辑、上传、预检都不触发 GPU 租赁；仍需用户确认提交任务。10 分钟无业务任务才停机，等待启动和结果收集都算业务工作。

方式选择采用原生 fieldset / radio / label，保留键盘选择和焦点显示；依据 [W3C Radio Group Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) 核对单选语义与方向键交互。

## 新的受控执行配置

`fl50` 保持原有文本生成兼容。显式 `fl50-firstlast4-ref4-v1` 支持两个 recipe，并要求新的运营 `runtime_required` 策略及逐实例验证，不能沿用旧 FL 实测回执冒充首尾帧验证。

每台 GPU 依次运行文本 FL50、4 步首尾帧兼容性测试、4 步 Ref 兼容性测试；后者含图片、视频原声、独立音频和复用图片锚点。使用自有程序图片和自产 FL 素材，保留输入尺寸、哈希、实际结果与耗时。4 步测试核对同一固定计算图的输入、内存与输出形状，不代表新输入的 50 步耗时或成片质量实测；用户任务仍可选择最多 50 步。未知提交只核对原任务，不重发；进入排空后只收集已提交测试，不启动下一项。

本轮拟开放的保守范围（最终以服务器 capabilities 和预检为准）：

- 输出 4–5 秒、最高 768p、最多 50 步；CPU 编码器、视频分块解码。
- FL：纯文字，或首帧 / 尾帧两张图片。
- Ref：一张图片、一段视频、一段独立音频；允许视频原声，可添加复用图片的时间锚点。
- 图片输入最多 2048×2048 的像素总量；视频最多 832×480 的像素总量、107/24 秒；独立音频最多 4.45 秒。
- 锚点仅为 Ref 图片锚点，最多一个；复用同一图片不重复计数。不能把这些限制描述为全部原生输入都已开放。

冷启动预留 3600 秒用于下载与三项验证，不是速度承诺；用户任务按 1800 秒保守检查期限。实际租赁受原有累计 US$50 预算、每周期价格上限和供应商 TTL 约束。新的配置不延长原服务期限、不重置预算、不创建凭据副本。

## 验证范围与发布证据

本地界面检查已覆盖桌面单选切换、提示词保留、对应上传区切换，以及 390px 宽度下模式选择先于素材和参数，无横向溢出。后端离线测试使用临时数据及假执行器，不能当作新 GPU 的首尾帧或多模态实测。

实际发布、公开 HTTPS 两账户预检、是否租赁 GPU 和最终 commit 单独记在 `.platform-demand-live/` 本轮回执中；本文件本身不代表已经部署。生产旧池有任何已接收任务时，不得使用“空池换版”维护脚本。所有旧控制器状态和配置先留档，账户、素材、数据库、SSH 身份和预算保留原位。
